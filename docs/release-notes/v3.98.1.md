## Fixed

- **The app was offering the wrong release as the update.** It asked each project for its releases
  and took the first one in the list, on the belief that GitHub returns them newest-first. It does
  not. Measured on ShadowMountPlus: the first entry was `1.7beta5`, published at 16:12, and the
  second was `1.7-beta5fix1`, published at 18:36 — two hours newer, and the one GitHub itself marks
  as the latest. Every lane now picks by when a release was actually published: the PC, the page,
  and both consoles' own update checks.
- **kstuff and FPKGi can be updated at all now.** Both were in the catalogue with no upstream
  recorded, so neither had ever had an update lane, and on a console with no PC their tiles could
  do nothing. Their real projects were found and checked file-by-file before being written down:
  kstuff's release carries a `kstuff.elf` of exactly the size the console is running, and FPKGi's
  carries exactly the package both consoles hold.
- **PS5SX2's helper was being looked for under two names that no longer exist.** Its newest release
  replaced the separate installer and helper with a single file, so the app was hunting for two
  things that had been gone for a release and finding neither.
- **Itemzflow stops being offered an update it cannot take.** Its releases carry a changelog and no
  files at all — the package comes from the in-console Homebrew Store — so there was never anything
  for the app to fetch. It says so now instead of looking like a broken update.
- **Deleting a backup removes every copy of it.** The console watches more than one folder, and
  delete removed only the first copy it found — so a game that existed in two of them came back on
  the next scan, and you had to press Delete again with nothing explaining why. It now clears them
  all and says how many it took.
- **A package sitting where your apps live is visible again.** The list of places the console looks
  for an installable package never included the folders the backup service actually watches, so a
  `.pkg` dropped beside your emulators — the most obvious place to put one — could not be seen.
- **PS5CEMU-HAR had no file pattern recorded**, and matched only because its release happens to
  carry exactly one archive. Named properly, so a second file in a future release cannot confuse it.

## Changed

- Firmware notes on the emulator tiles now say where the number comes from — "13.60 or below",
  "13.60 reported", "needs ShadowMountPlus 1.7beta4+" — rather than implying every project
  documents a tested ceiling. Two of them document none at all.
