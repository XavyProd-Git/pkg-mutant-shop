This release is about one situation: **a PC that has never held any of the files**. The app was
installed fresh on such a PC, with a PS4, and almost nothing in Payloads & Homebrews worked — while
it all worked on the one machine that already had everything. Every item below came out of that.

Below is what changed, by area. Every change with the measurements behind it is in the
[full changelog](https://github.com/XavyProd-Git/pkg-mutant-shop/blob/master/CHANGELOG.md).

## Fixed

### Downloading, from a PC that starts with nothing

- **A fresh PC can reach GitHub.** Windows only knows the certificate authorities it has already
  met, so on a new machine every GitHub address failed — and the app could only say "could not
  reach GitHub". The app now carries its own list as well, falls back to Windows' own network
  stack, and then to `curl`.
- **A failure says what failed.** No name lookup, no connection, a timeout, an untrusted
  certificate, a wrong clock, a rate limit or an error from the site: each has its own sentence,
  names the host, and is translated.
- **"Working…" ends.** A download used to run inside one long request with nothing on screen. It is
  a job now: a percentage, a **Cancel**, and it carries on from where it stopped if the connection
  drops. The button you pressed always comes back.
- **A tile for something this PC does not hold can still be pressed.** *Install* and *Send* fetch
  the file from the project first and then carry on — one press, as it should have been.
- **A download is checked before it is used** — its length, the checksum the project published,
  and that it really is a package, a payload or an archive and not an error page.
- **A download never replaces a newer copy you already have** with an older one.

### Update checks

- **Checks through a PC stop using up GitHub's hourly limit.** The PC reads releases from each
  project's own page instead of the rate-limited API, which three devices behind one address were
  sharing. A console checking on its own, with no PC answering, still uses the API.
- **A check takes seconds.** Every project is asked at once: twenty-four of them in about five
  seconds, where one slow site used to hold the panel for a minute.
- **One bad moment does not wipe what was known.** If a project cannot be asked right now, its row
  keeps showing its last answer. The answers also survive restarting the app.
- **A check that reached no project no longer says "Everything matches".** The drawer says it
  could not check, once, with the reason.

### Installing

- **A newer build of an installed homebrew installs.** DolphinPS4 was answered "already installed"
  because the new package was almost the same size as the old one. Versions are compared now.
- **Updating an emulator on the PC keeps what you put inside it** — games, saves and settings
  stored in the app's own folder were being deleted with the old copy.
- **The right file is picked for the right console**, including for a project whose *name*
  contains a console's name.

### The PS4

- **The PS4 can download on its own after all.** 3.98.4 said it could not. The real cause: the
  console allows eight secure connections' worth of setup per boot, and the app was using one for
  every request. It now sets up **one**, keeps it, and hands it on each time the app is loaded —
  checked on a freshly restarted PS4, which made exactly one across ten release checks and a
  download.
  **Restart the PS4 once after loading this build** — a boot that has already used its eight on
  an older version cannot get them back, and until then it will keep saying a PC is needed.

### Payload Manager 0.6.0

- **Works with Payload Manager 0.6.0.** It came out while this release was being tested and
  changed how payloads are started and where they are kept — on 0.6.0 the previous build of this
  app could not start its installer, so nothing could be installed on a PS5. Installing, Run,
  Send and updating the app all work with it now, and still work with 0.5.x. A new build of the
  app goes into the slot Payload Manager itself lists and autoloads.

### Finding each other

- **A console on another network adapter is found.** Only the network with the default route was
  searched, which is the wrong one whenever a VPN is up or Wi-Fi and Ethernet are both connected.
- **"PC found at <address> but it is not answering this console"** replaces a green "works with the PC off"
  when that is what is really happening — usually Windows Firewall.

## Added

- **Connection check**, in Settings. Every link, worst first, each with the one thing to do: this
  PC to the internet, this PC to each console, **each console back to this PC**, Windows Firewall,
  and whether a console can download by itself.
- **FPKGi gets its list.** A `GAMES.json` kept beside the package in your folder is put on the
  console when FPKGi is installed; an empty one is created if you have none. A list already on the
  console is not overwritten unless you send again.
- **New in the catalogue.** PS5: **PS4Mount**, **Y2JB Autoloader**, **PSP5**, **PSBox Cloud
  Gaming**, **Vita3K**. PS4: **Crema** (nothing published yet — its row says so).
- **When a PC installs an app, whatever it needs beside it goes too** — helper files, a line in
  a helper's allowlist, a file that has to sit at one exact path. A console installing on its own
  does not do this yet; the tile says what to do by hand.
- **The PS5 payload carries PS4Mount** with the other payloads it can start by itself, and
  Payload Manager 0.6.0.
- **"PC NEEDED."** When something needs a PC, that is what the page says.

## Known at the time

- **FPKGi on a PS5 needs etaHEN**, with its Direct PKG Installer switched on. It is the same
  package as the PS4's — there is only one — and on a PS5 without those services it installs and
  then does nothing. The tile says so.
- **The new PS5 entries were fetched and checked, not installed**, on the consoles this was
  tested with. Crema has nothing to fetch yet.

## Checked on hardware

- PS5 13.60 and PS4 13.52. From a PC with an empty folder: a payload and two packages fetched with
  progress, and DolphinPS4 taken from 04.04 to 04.06 on the PS4 in one press.
- The owner's `GAMES.json` delivered to both consoles and read back byte for byte.
- Payload Manager 0.6.0 on the PS5: an install, FTP starting at boot, and the app deployed into
  Payload Manager's own slot.
- On a freshly restarted PS4, with nothing but the console: ten release checks and a download
  (checked against the checksum its project published) through one secure-connection setup.
  Before that, one kept setup answering twelve checks and a download on a PS5 built the PS4's
  way, and the hand-over between two loads of the app on the PS4.
