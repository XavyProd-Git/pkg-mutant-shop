## Added

- **Eight emulators in Payloads & Homebrews.** DolphinPS4 (GameCube · Wii on the PS4), and on the
  PS5: RetroArch, PS5SX2 (PlayStation 2), PS5X360 (Xbox 360), XPSemu (original Xbox),
  ProsperoEden (Nintendo Switch), Porpoise (GameCube · Wii) and PS5CEMU-HAR (Wii U · 3DS). Each
  one says what it emulates and which firmware it was built for.
- **A Download drawer, beside the Updates one.** It lists everything the catalogue knows about for
  the console you are looking at — what you have and what you do not — and downloads any of it
  straight from the project's own latest release. Press it on something you already have and it
  asks first instead of fetching 200 MB again.
- **The files an emulator does not work without come with it.** PS5SX2's installer and helper,
  XPSemu's helper, PS5X360's log collector: all fetched in the same press, and a download where one
  of them did not arrive says so rather than reporting success.
- **Archives are opened for you.** Most of these ship as a `.zip`, which neither console can be
  handed — the projects tell you to extract it and copy a folder over FTP. The app now reads the
  archive, puts the app folder where the console takes it, and installs it from there. No FTP
  client, no manual step.
- **Emulator data goes to the right place on the console.** PS5SX2's PCSX2 folder — its patches,
  shaders, renderer flags and game database — is placed in `/data/PCSX2`, with the empty `bios/`
  and `games/` folders created so the emulator can find your own dumps. Nothing you have already
  changed is overwritten.
- **Each row says whether the console has it**, not only whether this PC does.
- **A build we cannot line up against its upstream can still be taken.** Those rows said "could not
  tell" and offered nothing; now they offer it, clearly labelled as your decision.

- **The Download drawer is two columns, in alphabetical order, one line an item.** It was two
  rows each, and for every emulator the second row repeated the first in different words -
  "PS5CEMU-HAR  Wii U · Nintendo 3DS" above "Wii U (Cemu) and Nintendo 3DS (Azahar) on the
  PS5." Eighteen items used to make thirty-six rows and 1,519 px of scrolling; they now make
  eighteen rows and 451 px, which fits without scrolling at all. A green dot marks what the
  console already has, and the full description, the firmware and the setup note are on the
  row's tooltip.
- **The Updates drawer had the same treatment.** It was listing both consoles at once - on a PS5
  tab, five of the rows were PS4 payloads - and writing "PS5" beside the other fourteen on a
  panel whose header already says PS5. It shows the console you are looking at, so the label has
  nothing left to say. The app's own update row printed the new version twice, forty pixels
  apart. The "could not be compared" entries were paragraphs that pushed their own button onto a
  second line; they are now the same three slots as every other row.

- **The app installs itself where each console's payload manager looks.** Downloading it,
  updating it or sending it now also places the ELF in `/data/pldmgr/payloads/PKG-MUTANT-SHOP`
  on the PS5 and `/data/payloads` on the PS4 — so after a reboot you can start the shop from
  Payload Manager or GoldHEN's own menu, with no PC awake. Only this app's own payloads are
  placed; every other payload goes exactly where it always did.
- **Six ways in, all of them covered:** both Send buttons, the Download and Update rows, the
  "it was already there" shortcut on the PS4, and the automatic hand-over when a PS4 comes up
  with no shop running. A console that is asleep is simply reported — a download still works
  with everything switched off, exactly as before.
- **The Download drawer shows one row an item, in two columns.** The name is in the accent
  colour so it reads apart from the description, and it stays that colour on something you
  already have. Hovering a row gives the full description, the firmware it was built for and
  any setup note.

- **Every payload and homebrew offers what it can actually do.** Press a tile and it names the
  next step rather than guessing at one: a payload offers Run and Send again, a homebrew offers
  Install or Send again, and something no machine has yet offers Download. A first install still
  happens on one press — it is only when there is more than one thing a press could mean, or
  when the app cannot tell what state the console is in, that it asks.
- **The helper payloads two of the emulators need are now in the panel.** PS5SX2 and XPSemu do not
  start unless their helper is running — their own notes say so — and the app had been
  downloading those files into the folder beside the emulator where nothing could launch them.
  They appear as payloads of their own now, named after the app they belong to, with Run and Send
  where every other payload has them. PS5SX2's installer and PS5X360's log collector come too.
- **A tile's tooltip says what it takes to make the thing work**, and which machine is holding the
  file. The setup note and the firmware were on the Download drawer's rows and vanished the moment
  you owned the item; and a press that was about to pull a quarter of a gigabyte across from your
  other PC looked exactly like one reading a local file.

- **A package the console is already holding is installed from the console's own copy.** Nothing
  is transferred. The app had been working this out and then throwing the answer away: the tile
  said the console had it and the only button answered "not on this PC".
- **"Keep on the console".** A package copied into the console's own folder can be installed again
  with every PC switched off, which is the only way a console can be self-sufficient — the
  packages are far too large to live inside the app. Offered on a tile you have already installed,
  beside Send again.
- **The choice row works with a controller.** Those two buttons were reachable only with the
  stick cursor; they take D-pad focus and Enter now.

- **The shop puts its own listening socket back when it stops working.** Both consoles now notice
  that they have stopped accepting connections, throw the dead socket away and bind a new one. This
  is what turns "the app is gone and the only way back is a reboot" into a few seconds of silence.
- **A new copy waits thirty seconds for the old one to let go**, instead of five, and says what is
  actually wrong if it cannot have the port — the old message was "already running, no need to
  load it again", which was the one thing the owner saw from a console that was serving nothing.

- **The consoles serve card-sized covers of their own.** A companion leaves a small copy of each
  cover on the console while it is connected, and the console serves those from then on — with
  every PC switched off. The PS5's library went from 23 MB of artwork to 4 MB. A title with no
  small copy yet is served the original, so nothing is ever missing while the cache fills.

- **Both consoles download and update on their own, with every PC switched off.** Payloads &
  Homebrews used to answer "a PC running this app has to fetch it" on a console with no companion,
  because neither console had ever spoken to a project's release page. Now each one reads what a
  project has published, picks the file that matches that console, downloads it, checks it against
  the SHA-256 the project stated, and installs it when it is a package. Get more, Update and Update
  all are all real buttons there now — including the app's own new build, which the console
  fetches for itself.
- **Updates are compared for everything installed, not only for files on the console.** An emulator
  is a folder app with no package left behind, so every one of them was skipped: the drawer read
  "1 update" on a PS5 that had five. They are all compared now, and a row the app cannot line up
  — a folder app's own `01.00` against a release called `v1.0.0-beta.1` — says so instead
  of staying silent.
- **A download is checked before it is kept.** The release states a SHA-256 for every file; the app
  hashes what arrived and refuses anything that does not match, so a truncated or substituted
  download never reaches the name something would run. The two numbers come from two different
  servers, which is what makes the check worth making.
- **One version of a payload in a folder, never two.** A new release usually has a new file name,
  so the previous copy used to sit beside it and both looked like the same project. The old one is
  removed as the new one lands.

- **The console remembers which release it took.** Update a payload or homebrew from the console
  and the app writes the release down beside the file, so the panel compares against what your
  console is actually holding instead of against the version recorded when the app was built.
  That is what stops a row offering an update you have already taken.
- **Run starts the copy you downloaded.** Taking an update used to leave the new file beside the
  one the app ships and then start the shipped one.
- **A Cancel while a download is running.** An Update pressed by mistake is 46 MB for the app's
  own build and up to 268 MB for a package, and while one runs the console will not start another
  — so both drawers were stuck for the duration with no way to stop it.
- **"Update all" carries on and tells you how many it took.** It used to stop at the first row it
  could not take, leaving every payload behind it untouched and saying nothing about it.

## Fixed

- **A just-downloaded emulator reported an update to itself.** An app folder's own version number
  (`01.00`, for ever) was being compared against a release tag like `v2.5` or `Alpha-2`, so all
  three read as permanently out of date. Downloads now record which release they came from, and a
  folder installed by hand is honestly reported as not comparable.
- **Things already downloaded went on being offered.** An emulator is identified by the title id
  inside it and the offer by the name of the project, so neither recognised the other: three
  emulators were downloaded, unpacked and installed while the drawer kept offering all three.
- **The Download drawer counted things it could not download.** A project that publishes no build
  was included in the count beside the button.
- **Items not downloaded yet appeared in the update list** as rows reading "no version to compare",
  under a heading about things that could not be checked.
- **Asking what an install would do performed part of it.** The emulator-data copy ran before the
  step that honours a dry run, so a dry run wrote 56 files to the console. It reports them now.
- **Installing an archive copied the archive.** It went to the folder the console watches, where
  nothing would ever mount it — a slow, silent nothing.
- **RetroArch had no upstream recorded**, so no update for it could ever be found. Two separate
  catalogue entries described it; they are one entry now.

- **PS4: the library scrolls properly.** The covers were the whole story. Every small-cover path
  was gated on WebP, which that browser does not have, so each card fell through to the
  **full-size 512 px original** - measured over your own artwork, 317 KB a cover and **19.4 MB for
  one screen of 64 cards**, plus about two and a half times the pixels to decode. The same 320 px
  thumbnail is now also made as a JPEG, which it can read: **1.8 MB a screen, eleven times less**,
  at the same size on screen from the same source image. The PS5 is untouched and keeps WebP.
- **PS4: everything else that scrolls, too.** The console-specific rules switched off shadows on
  four things, two of which never had one, and missed every box in the app whose contents
  actually scroll - the game drawer, the panel and settings sheet, the queue dock, the overflow
  menu and the tooltip, each wearing a 40-54 px blur that is redrawn as the content moves. They
  are covered now, along with the two pills that animate a blur as the cursor arrives, the
  settings page's sticky header and third column, the two forever-animations inside the queue,
  and the colour filter on every disabled button. Nothing is removed: same layout, same artwork,
  same information, and the PS5 and phones are unchanged.
- **The library asked the browser to re-measure the page six times per frame while scrolling**,
  for a number that only changes when the window resizes. Measured: 191 forced layout flushes
  over thirty scroll steps, now 70.
- **Two things were painted under every cover and then hidden by it** - the card's colour
  gradient and its large blurred initials. On a full screen that is 53 of each, drawn and
  immediately covered. A card whose artwork fails to load still gets both back.
- **The panel rebuilt both drawers every three seconds**, open or shut, changed or not - which
  resets your scroll position and throws away the row under the cursor. They are only rebuilt
  when something in them actually changed.
- **Closing the panel left the Download drawer floating over the library.**
- **A tooltip followed the cursor down the list while you scrolled**, re-measuring the page each
  time; and a menu-closing handler wrote to the page on every scroll tick whether a menu was
  open or not.

- **The Download drawer listed some things twice**, once offering a fresh download of something
  already downloaded, installed and running. With two PCs, the one your console happens to be
  talking to may be missing a file the other one holds — the two descriptions of the same
  program were not recognising each other. "You have this" now means anywhere the app can see
  it: this PC, the other PC, or installed on the console.
- **The Download drawer opened upwards**, flying the list to the top of the screen instead of
  dropping from its button.
- **"Could not be compared" is gone** from the Updates drawer. Those rows are still there,
  dimmed, with the reason when you hover them.
- **Names in the Download drawer went grey once you had the item**, which made every row look
  switched off. Only the description and the button dim now.
- **PS4: panels and sections open without the pause.** A panel that has never been opened was
  being laid out from nothing in the same frame as its animation — Settings cost about twelve
  times what it costs now. They are prepared quietly a couple of seconds after the app starts.
  The game panel also stayed in the page's layout permanently while hidden, so it was being
  measured on every scroll of the library.
- **PS4: the library does less work for the same picture.** The page was re-measuring itself six
  times a frame while scrolling, rewriting a filter chip that had not changed on every refresh,
  and saving a 200 KB copy of your library in between receiving it and drawing it. Filtering and
  sorting also did several passes over every title that one pass now covers. Nothing on screen
  changed — verified against the old code over four hundred comparisons.
- **The game panel could collapse to one column while you were reading it.** Changing the console
  in an open panel left a timer running from the previous draw; nine hundred milliseconds later
  it decided the panel's right-hand side was empty and threw it away, mods list included.

- **Folder apps were not being installed at all.** Every emulator on the PS5 that ships as a
  folder rather than a package — PS5SX2, PS5X360, Porpoise, ProsperoEden, RetroArch, XPSemu —
  answered a press with "A folder app — it goes on a drive the console mounts" and then did
  nothing. The app has been able to install them the whole time: they go to the drive
  ShadowMountPlus watches, by the same route a game stored unpacked takes. It was the panel
  refusing, not the console. Verified end to end on a PS5: installed, mounted, and listed by the
  console afterwards.
- **A payload that was not running had no way to be replaced.** The only thing a press could do was
  start it, so a payload whose file needed sending again had to be started first.
- **A tile for something no machine held did nothing but complain.** It offers the download now.
- **The console on its own no longer offers a button it cannot honour.** With no PC awake, the
  panel assumed every payload in the catalogue was one the console carries. It is not — a
  helper lives in your folder, and the app's own entry is the program serving the page rather than
  a file — so those were Run buttons whose only possible answer was "this build does not carry
  that one". The console is asked what it actually has.

- **"<name> is not on this PC" about a file that had just been downloaded onto it.** The list of
  servable files is built when the app scans your library, and a scan is a moment — everything
  this panel downloads arrives after it. The install step was reading that snapshot as if it were
  the disk. It asks the disk now. This is the DolphinPS4 case.
- **Tiles claiming "Not on this PC" for things the console had installed.** The app ships a
  record of the folder it was built from, and every entry in it said "you have this file" — true
  on the machine that built the release, wrong on yours. So the Download drawer hid the item
  ("you already have this") while the tile refused to install it, and with the other PC switched
  off there was no way to get it at all. Whether a file is here is now read off your own disk, on
  every path, including the one where the folder cannot be reached.
- **Reading the panel twice could change what it listed.** That same record is shared, and the
  merge wrote into it — so the second read saw every entry marked "not here", stopped matching
  the download offers against it, and listed seven programs twice, DolphinPS4 among them. One
  row offering a download, one row refusing to install.
- **An installed homebrew read "Not on this PC" inside a green tile**, and pressing it said so
  again. The colour and the words were answering in opposite orders.
- **One press could start a payload that changes the jailbreak layer** — kstuff, OnionHEN, the
  WebKit installer — because the panel always sent its own confirmation. They open the row first
  now, like everything else.
- **An open choice row was rebuilt every three seconds**, throwing away the button under your
  finger.
- **A press could act on what the tile showed three seconds ago**, not what it shows now.
- **A payload only your other PC has could not be sent.** The check for "do I need the bytes"
  answered "no" precisely because this PC had none.
- **A console holding a newer release of a package than the app knew about was invisible.** Its
  own copy was matched by exact byte count against a size recorded elsewhere; the title id is
  used as well now, which is what survives a new version.
- **The other PC's reason for refusing was replaced by this one's.** Any refusal it gave arrived
  as an error and was discarded, so "that one is for a PS5" became "it is not on this PC".
- **One unreadable item in your folder stopped every homebrew being installable.** The whole list
  was abandoned at the first problem; it is per item, and the log names the one that failed.
- **The PS4 answers the panel's own routes with a reason** instead of an empty reply, so a press
  that cannot work says why rather than "That did not work".
- **The Download and Updates drawers say they need a PC** when none is answering, instead of
  offering buttons no console can honour. Neither console can reach the internet by itself.

- **The PS4 could stop answering entirely, with the port still open.** Its listening socket stopped
  accepting connections and the shop had no way back: every browser got "the connection was
  forcibly closed", and loading the payload again answered "already running". Found in the
  console's own log — 119,000 consecutive failures over about forty minutes. The recovery the code
  already had could never run, because it tried to bind the replacement socket while the old one was
  still listening on the same port, which this kernel refuses. It closes the old one first now. The
  PS5 had the same loop with no recovery at all; it has one.
- **A new network never found the PS4.** The app only accepted a console its own shop was already
  answering on, or a PS5 with Payload Manager running — and a PS4 that has just booted has
  neither, because its payload does not survive a reboot. It is recognised by GoldHEN naming itself
  now, so a console with nothing of ours on it yet is still found, and the address no longer has to
  be typed in. Verified against the console with its shop down and its payload loader refusing
  connections.
- **...and once one console was found, the app stopped looking for the other.** It swept the network
  only while a console it already knew about was silent, so a PS5 that answered meant the PS4 was
  never looked for again. It keeps looking while either console is unknown, and stops once both are.
- **The PS5 never told the app which console it was.** Its own reply carried no id and no platform,
  so on the console itself every panel that picks a console by id had nothing to pick. The PS4 has
  always sent both.

- **With no PC awake, the library asked a PC for every cover.** `thumb_url` and `icon_url` are a
  companion's own addresses, written onto each title and still handed out by the console long
  after that companion has gone. Measured in the console's browser with both PCs off: every cover
  pointed at `http://10.0.0.76:8710/...` and sat there unfinished — a connection to a machine
  that is not on the network does not fail quickly, so the card never painted and never fell back
  to initials either. That is the slow, half-loaded library, and the covers that faded on
  scrolling and did not come back. On that lane the console's own art is used now, always.

- **A client that hung up mid-transfer could take the PS5 shop down.** Writing to a closed socket
  raises SIGPIPE, whose default action is to end the process — and this is the build that
  streams multi-gigabyte packages to the console's own installer and card art to a browser that
  abandons image loads as you scroll. The PS4 has ignored that signal for some time; the PS5 had no
  protection at all.
- **An archive still needs a PC, and now says so.** Five of the emulators ship a `.zip`, which has
  to be unpacked into a folder on a drive; neither console has anything to unpack one with. Those
  rows name a PC and explain why, and the Updates drawer links to the project's own page instead of
  offering a button that cannot finish.
- **A console running an older build no longer reads as "nothing to report".** Both consoles answer
  an unknown request with an empty reply, so a console that cannot check for updates looked exactly
  like one with nothing to offer. It says which.

- **The Updates drawer only ever filled in when a PC was running.** Opening Payloads & Homebrews
  started the catalogue loading and the update check in the same breath, so with no PC the check
  ran against a list that was still empty, found no projects to ask about and reported nothing
  — which on that drawer is indistinguishable from "everything is up to date". A PC hid it
  completely, because a PC answers the whole question in one reply. It waits for the list now, and
  asks every project at once instead of one after another: the first row appears in about four
  seconds and the drawer fills as the answers arrive, rather than sitting blank for over half a
  minute.
- **A project the console had not answered about yet counted as checked.** The page gave up after
  seventeen seconds and then used the "still working on it" reply as though it were an answer, so
  rows read "1.16-ng-stable → ?" and blamed the projects for files they had not been asked
  for — under a green "Everything matches the newest release".
- **"Check for updates" could not refresh anything.** The request said "ask again", but the polls
  that followed it did not, so the answer already in hand satisfied them and GitHub was never
  asked. A release cut in the last six hours was invisible however many times you pressed it.
- **A cancelled download left the button spinning**, as did an update whose job never appeared.
- **"Take it anyway" was offered on rows nothing on the console can take**, answering every press
  with the same refusal. Those rows keep their link to the project's page instead.
- **A package with no file extension recorded was downloaded and never installed** — Itemzflow
  on both consoles. DolphinPS4 happened to work, so the same button worked for one row and
  silently half-worked for another.
- **A package the console downloaded for itself was invisible to the panel afterwards**, because
  it went to a folder the console does not list. After a failed install the tile said "Not on this
  console" about a file sitting on its own disk, and the only way forward it offered was to
  download the whole thing again.
- **Every row in the Download drawer looked already-downloaded**, because the catalogue's record of
  what the machine that built it was holding was being read as a fact about your console. The
  count badge could never be anything but zero.
- **A tile for something the console does not have offered nothing at all**, while the Download
  drawer one row up would fetch it.
- **"Send again" on the console described the one thing that was not happening** — nothing is
  sent; the console reads the package off its own disk.
- **Taking the app's own release said "Downloaded"**, which reads as "updated". The new build is on
  the console but the old one keeps running until you start it, and it says that now.
- **The app's own update check could hang for ever** if GitHub accepted the connection and never
  answered, leaving the drawer at "Working..." until the page was reloaded.
