## Fixed

- **The library's artwork loads straight away on a console with no PC.** It was asking for each
  title's **full-size original** instead of the card-sized cover the console had already made —
  measured across a 68-title library, **23.0 MB where 2.2 MB was needed**, one cover 461,681 bytes
  where 38,432 would do, and each 512×512 image costing about a megabyte of memory to decode on
  top of that. The small covers existed the whole time; the page simply never asked for them.

  The cause was a race the page could not win: it only asked for the small cover once the console
  had confirmed it serves them, and the library is drawn before that confirmation arrives. Nothing
  re-drew a cover afterwards, so whatever the first draw chose, you were stuck with for the rest of
  the page's life. It now asks for the small cover from the start — a console serving its own page
  is running the same build, so the answer is already known — and a cover that somehow slipped
  through at full size is swapped the moment the console confirms.

- **A cover that never started now starts.** Covers are loaded only when they come near the screen,
  which is right, but that decision is made by the browser and when it never arrives the cover
  never appears at all. Measured: 54 covers all asking for the correct file and not one of them
  begun after seven seconds — and every one of them finished within a second of being asked
  directly. A few seconds after the library settles, anything that has not even begun is now asked
  for outright. That is the *"sometimes it never loads them at all"*.
